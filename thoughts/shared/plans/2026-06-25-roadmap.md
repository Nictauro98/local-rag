# Local RAG — Portfolio Roadmap

> Program overview for the privacy-first local RAG system. Source spec: [`../../local_rag_implementation_plan.md`](../../local_rag_implementation_plan.md).
> Four MVPs, each an independently shippable, demoable milestone. A React frontend is documented as future work, not yet planned.

## Thesis

A **production-grade, privacy-first RAG system** that runs entirely on local / company-controlled infrastructure. Documents never leave the perimeter (GDPR / LGPD / Ley 25.326). Every external-facing concern — object storage, embeddings, LLM, observability — is either self-hosted or behind an adapter interface so an AWS migration touches only the adapter layer.

## Decisions locked for this program (deltas from the original spec)

These were decided collaboratively on 2026-06-25 and apply across all plans:

1. **Ingestion uses an `arq` + Redis task queue**, not FastAPI `BackgroundTasks`. Durable jobs, retries, real status tracking. Adds a Redis service and an `arq` worker container. Rationale: "production pipeline" signal + actual durability.
2. **UI stays Streamlit** through MVP 1–4. A React/Next.js frontend is deferred to a future plan (the FastAPI layer is already the clean seam for it).
3. **Observability is Langfuse, self-hosted, introduced in MVP 3** — *after* the eval layer, because it visualizes the eval scores MVP 2 produces. It does **not** replace the MVP 2 eval logic; it's the scoreboard for it.
4. **Retrieval stays dense top-k** through MVP 1–3. Hybrid search + cross-encoder reranking is **MVP 4**.
5. **Package/tooling:** `uv` for dependency management and runs; `ruff` + `black`; `pytest` + `pytest-asyncio`. Matches existing project conventions.

## Architectural invariants (enforced by every plan)

- Business logic in `src/core/`, `src/nodes/`, `src/evaluation/` imports **no concrete adapter** — dependencies are injected via function parameters.
- Adapters implement an interface in `src/interfaces/`. AWS stubs (`s3_storage.py`, `bedrock_embedder.py`) exist from MVP 1 with `NotImplementedError` + migration docstrings.
- Configuration is environment-only via `pydantic-settings`; `.env.example` documents every variable. No hardcoded model names or URLs.
- Only `langchain-text-splitters` is permitted from the LangChain ecosystem. No retrievers/chains/agents.
- `handlers/lambda_handler.py` stays a thin adapter; any logic belongs in `core/`.
- The full stack comes up with `docker compose up`. CPU fallback for Ollama is documented.

## Future work (not planned yet)

- **React/Next.js frontend** — streaming answers, source highlighting, eval dashboard. The FastAPI API is the contract; Streamlit can be retired or kept as an internal tool.
- **AWS migration execution** — the adapter seams and Lambda handler exist from MVP 1; this would be the actual deploy (S3, Bedrock, OpenSearch/Pinecone, ECS/Lambda).
- **Multi-tenant auth** — out of scope for a local portfolio demo.
